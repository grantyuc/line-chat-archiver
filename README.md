# LINE 聊天記錄封存

把 LINE 手機版匯出的純文字聊天記錄，和手機畫面擷取、手機上的貼圖與照片快取結合，輸出成離線可看、LINE 風格的靜態網站：

- 文字來自 txt，可以反白、Ctrl+F，首頁還能搜尋全部月份；從搜尋結果點進訊息後，頂端的搜尋列可以直接跳到上一個／下一個結果（跨月份也可以；鍵盤 Enter／Shift+Enter），或返回搜尋結果。
- `[貼圖]` 換成貼圖原檔（含動畫），`[照片]` 換成快取中的一般版或原檔，點開可放大；放大後再點一下照片可以再放大（窄長的照片放大到畫面寬度、上下捲動），再點一下縮回。
- `[語音訊息]` 可以直接播放（快取中還有語音檔時）。
- 文字中的 LINE 表情（`(呵呵呵)`、`(Happy)` 等）顯示成圖片：只傳表情的訊息在畫面上是大圖，從截圖裁下來學到每個名稱的樣子，再換掉所有文字中的同名表情。
- 訊息下方的回應（表情回應）顯示在泡泡下方。
- 依月份分頁，避免單一頁面太大；訊息少的月份和相鄰月份合併成一頁。
- 首頁的搜尋框也可以輸入日期（`2024/7/2`、`2024-07-02`、`2024年7月`），直接跳到那一天；那天沒有訊息時跳到之後最近的一天。
- 預設淺色，聊天背景和泡泡的顏色取自截圖，和手機上一樣；標題列的 🌙 可以切換成深色（瀏覽器會記住）。

不需要 Root。手機需開啟 USB 偵錯。設計依據見 [`poc/README.md`](poc/README.md) 的實機測試。

## 運作方式

| 步驟 | 指令 | 做什麼 |
|---|---|---|
| 1 解析 | `parse` | 解析 txt：日期、時間、發話者、訊息類型 |
| 2 擷取 | `capture` | 從最新訊息往上捲，每一步截圖＋uiautomator dump，到最舊的訊息自動停止 |
| 3 輸出 | `build` | 合併各步畫面去重 → 和 txt 逐則對齊 → 從手機快取取得貼圖和照片 → 產生網站 |

照片取得方式：聊天畫面上顯示的就是快取裡的縮圖，所以先拉回縮圖比對，找到對應的訊息編號後，只拉那一則的最佳版本（原檔 > 一般版 > 縮圖）。縮圖比對不到的照片，先重新列出這個聊天室的快取（擷取畫面時 LINE 可能才下載了舊照片的縮圖）再找一次，再逐一比對前後已對到的照片之間的編號（包括快取中沒有縮圖、只有大圖的訊息）。仍找不到的貼圖和照片用截圖裁切。

## 安裝

1. Android SDK Platform-Tools（`adb`），並加入 PATH。
2. Python 3.10 以上：
   ```
   pip install -r requirements.txt
   ```
   其中的 uiautomator2 用來加速擷取。第一次擷取時，它會在手機上安裝一個服務 App（ATX），手機若跳出安裝確認請允許。

## 封存一個聊天室

以下以「威廷(Waiting)」為例，工作目錄用 `work/waiting`。`work/` 已加入 `.gitignore`，不會被 commit。

1. **匯出 txt。** 在手機上打開聊天室 → 右上角選單 ≡ →（其他）設定 → 傳送聊天記錄，把檔案存到電腦，例如 `chats/waiting.txt`。

2. **解析 txt：**
   ```
   python main.py parse chats/waiting.txt --work work/waiting
   ```
   會印出訊息數、日期範圍、各類型數量，以及判斷出的「自己」是誰。

3. **準備手機：**
   - 解鎖，打開這個聊天室，停在最新訊息（最底部）。
   - 開啟勿擾模式，避免通知橫幅蓋住畫面。
   - 讓螢幕保持常亮：`adb shell svc power stayon usb`（全部做完後執行 `adb shell svc power stayon false` 還原）。

4. **擷取畫面：**
   ```
   python main.py capture --work work/waiting
   ```
   - 過程中不要碰手機。會印出每一步的平均秒數，每 20 步和結束時再列出各階段（拖曳、dump、截圖、比對、存檔）各花多少時間。沒裝 uiautomator2 或連不上時自動改用 adb，約 6 秒一步。也可以用 `--backend u2` 或 `--backend adb` 指定。
   - uiautomator2 模式每步捲動的距離依畫面調整：盡量捲遠（最多聊天區的 3/4，`--drag 0.75`），但最上面被切掉的那一列，捲完後下緣要留在畫面內，所以每一列（包括很高的照片）都會完整出現在至少一張截圖裡。adb 模式的滑動有慣性，固定每步半個聊天區。
   - 若出現「捲了 …px，比預期的 …px 遠」的警告，代表放開時畫面還在慣性滑動，請回報。
   - uiautomator2 模式用兩條連線：拖完最後一段後立刻 dump，同時另一條連線放開手指、稍等圖片載入再截圖。每 20 步另外印出連線數和各請求平均時間（`injectInputEvent` 是觸控事件）。
   - 到最舊的訊息會自動停止：畫面上出現 txt 最前面的訊息（只用整段對話中獨一無二的文字訊息比對），又連續 3 步捲不動，才算到頂。
   - 捲不動但還沒到頂時：第一次立刻換個位置再拖（可能按到會攔住觸控的列）；之後多半是 LINE 正在載入更舊的訊息，每隔 1 秒換個位置再拖，載入完馬上繼續。約一分鐘仍捲不動就先停下，不標成完成，並提示檢查手機畫面。沒有先 `parse` 時無法對照最舊的訊息，連續約 20 秒捲不動就當作到頂。
   - 按 Ctrl+C 可以中斷。再執行同一個指令會接續：先確認畫面和最後一步有重疊，再繼續往上捲，所以中斷後不要捲動聊天室。中斷時若剛好拖完一步還沒存檔，畫面會比最後一步多捲一段，接續時會自動往回捲找到上次的位置。已標成完成的再執行，也會再試著往上捲，確認真的到頂。

5. **輸出網站：**
   ```
   python main.py build --work work/waiting
   ```
   - 第一次會拉回貼圖快取（約數百 MB）和照片縮圖，之後重用。
   - 聊天室的快取目錄會用照片自動找出來；也可以用 `--chat-dir u…` 直接指定（測試 7 的方法）。
   - 每個月一頁；訊息少於 300 則的月份會和相鄰月份合併成一頁（例如 `2021-03_2021-08.html`），首頁列出每一頁的範圍和則數。用 `--page-min 500` 合併得更多，`--page-min 0` 維持每月一頁。改分頁要重跑 `build`（快取會重用）。
   - 完成後打開 `work/waiting/site/index.html`。

也可以用 `python main.py run chats/waiting.txt --work work/waiting` 一次做完 2～5。

### 有新訊息時

不必重新擷取，只要補上新的部分：

1. 重新匯出完整的 txt（LINE 匯出的一定是全部記錄），再解析一次，會覆蓋 `chat.json`：
   ```
   python main.py parse chats/waiting-new.txt --work work/waiting
   ```
2. 手機上打開聊天室、停在最新訊息，執行更新擷取：
   ```
   python main.py capture --work work/waiting --update
   ```
   一樣從最新的訊息往上捲，畫面接上上次擷取的第一張（當時最新的畫面）就自動停止。存在 `capture/updates/001/`，下次更新是 `002/`，依此類推。中斷後再執行同一個指令會接續同一段。
3. `python main.py build --work work/waiting` 會把各段由新到舊串起來，和新的 txt 重新對齊，輸出整個網站。`report.txt` 會列出每段更新是否已接上。

也可以一次做完：`python main.py run chats/waiting-new.txt --work work/waiting --update`。

### 只想先看文字

只執行 `parse` 和 `build`（不 `capture`），網站會有全部文字，貼圖和照片顯示為佔位符。

## 檢查結果

`work/<名稱>/report.txt` 會列出：

- 擷取時判定不了位移的步數，以及輸出時重新比對（截圖、dump）或用估計值補上的結果。
- 各類型訊息對到畫面的數量，例如 `photo：41 / 42`。一次傳多張的照片在畫面上只有一列，會註明有幾則是和同一批照片共用一列。
- 低信心的配對，以及畫面上多出來、對不到 txt 的列（例如「以下為尚未閱讀的訊息」）。
- 貼圖、照片各有幾則來自快取、幾則用截圖裁切。
- 每則貼圖、照片、影片最後拿到什麼：快取、依編號推斷、截圖裁切，或沒有圖。改用截圖的會逐則列出裁切檔的位置；照片還會列出前後已對到的照片之間有哪些快取編號、各有哪些檔案、比對的一致比例（0.85 以上算同一張）。

有問題時，請貼回 `report.txt`。

## 除錯工具

檢查一份 uiautomator dump 解析出哪些列：

```
python main.py inspect poc/out/t2_media.xml
```

會列出每一列的位置、類型、左右側、時間、發話者。類型是 `unknown` 的列會列出它的元件 id，方便新增支援；加上 `--tree` 會印出未知列的完整元件樹（不含文字訊息內容）。

印出元件 id 含有某段文字的列的完整元件樹，例如訊息下方的回應（表情）：

```
python main.py inspect work/waiting/capture/00123.xml --match reaction
```

找出某則訊息在哪一步的畫面（`build` 之後），並印出檢查那一步的指令：

```
python main.py find "那則訊息裡的一段文字" --work work/waiting
python main.py find 2025/5/22 --work work/waiting
```

找出含有某種訊息的畫面，例如一次傳多張照片的「變更為格狀模式」：

```
grep -l "變更為格狀模式" work/waiting/capture/*.xml | head -1
```

## 工作目錄內容

| 路徑 | 內容 |
|---|---|
| `chat.json` | 解析後的 txt |
| `capture/` | 每一步的截圖（uiautomator2 為 `00012.jpg`，adb 為 `00012.png`）、dump（`00012.xml`）、`steps.jsonl` |
| `capture/updates/001/` | 第一次更新擷取（新訊息），結構同上 |
| `cache/` | 從手機拉回的貼圖快取、照片縮圖與大圖、索引 |
| `alignment.json` | 每則訊息對到哪一步的哪一列 |
| `media.json` | 每則訊息的媒體檔與來源 |
| `site/` | 輸出的網站 |
| `report.txt` | 報告 |

## 目前的限制

- 只支援繁體中文介面的匯出格式與 LINE 畫面。
- 訊息貼圖（自己輸入文字的貼圖）：快取裡只有底圖，截圖比底圖多出明顯的內容時改用截圖裁切，報告中列為「訊息貼圖（用截圖）」。
- 貼圖拼拼樂（多張貼圖組合）：整組從截圖裁切成一張（不會動），報告中列為「貼圖拼拼樂（用截圖）」。
- LINE 表情只有在聊天室裡出現過「只傳這個表情」的訊息（而且擷取到了）才認得；沒出現過的仍顯示 `(名稱)` 文字。回應的圖示同樣從截圖裁切。
- 影片只有在快取中有 MP4 時才能播放，否則只顯示縮圖。顯示為 [照片] 的動圖（快取中是 GIF，或被 LINE 轉成 MP4）會在網頁上直接循環播放。
- 只有縮圖的照片（測試聊天室約 12%）目前就用縮圖；尚未整合「照片・影片」批次下載。
- 檔案、位置、通話、LINE Pay 等訊息只顯示 txt 中的文字。
- 語音訊息沒有畫面可以比對，靠快取編號的順序（介於前後已對到的照片、影片之間）和長度（畫面上顯示的秒數）對到語音檔；快取中沒有的顯示為 `[語音訊息]`。
- 一次傳多張照片時，聊天室顯示成可左右滑的橫排，畫面上只露出前兩張。露出的照片照常比對；其餘的依快取編號推斷（同一批照片的編號相鄰），報告中標為 `inferred`。若快取中缺了某張，該張顯示為佔位符（報告中的 `photo:hidden`）。
- 收回通知不在 txt 裡；畫面上擷取到的會插回網頁中對應的位置。

## 開發

```
pip install -r requirements-dev.txt
python -m pytest
```

測試用模擬手機（`tests/fakechat.py`）產生和實機結構相同的截圖、dump 和快取，可以不接手機跑完整流程。
