# 實機測試（PoC）

開始寫正式程式之前，先在要用的手機上確認 6 件事。每項的結果都會改變後續設計，影響寫在各節的「判讀」。

| # | 要確認的事 | 腳本 | 約需時間 |
|---|---|---|---|
| 0 | 裝置資訊、adb 能不能模擬觸控 | `t0_device_info.py` | 5 分鐘 |
| 1 | 貼圖快取存不存在、讀不讀得到 | `t1_stickers.py` | 15 分鐘 |
| 2 | uiautomator 能不能讀到訊息文字與座標 | `t2_ui_dump.py` | 20 分鐘 |
| 3 | txt 匯出的實際格式 | `t3_export.py` | 30 分鐘 |
| 4 | 聊天室能不能截圖、截圖速度 | `t4_screencap.py` | 10 分鐘 |
| 5 | 連續滑動的位移、重疊、停穩時間 | `t5_swipe.py` | 30–60 分鐘 |
| 6 | 照片批次下載與縮圖對位 | `t6_media.py` | 30 分鐘 |
| 7 | 聊天媒體快取裡有沒有照片原檔 | `t7_chat_media.py` | 15 分鐘 |

建議順序：0 → 4 → 2 → 1 → 3 → 5 → 6 → 7。測試 4 若顯示截圖被擋，整個 ADB 截圖路線就不可行，其他測試可以先停。

所有指令都在 repo 根目錄執行。

---

## 準備

### 電腦

1. 安裝 [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools)，把 `adb` 加入 PATH。執行 `adb version` 有輸出即可。
2. 安裝 Python 3.10 以上，然後：
   ```
   pip install -r poc/requirements.txt
   ```
3. Windows 用 cmd 或 PowerShell 執行 `python ...` 都可以。不要自己用 PowerShell 的 `>` 存截圖：舊版 PowerShell 會把二進位資料當文字轉碼，檔案會壞掉。腳本內部已經處理好這個問題。

### 手機

1. 開啟開發者選項：設定 → 關於手機 → 連點「版本號碼」7 次。
2. 開發者選項 → 開啟「USB 偵錯」。
3. 小米／紅米（MIUI、HyperOS）：另外開啟「USB 偵錯（安全性設定）」，否則無法模擬滑動。其他品牌如果測試 0 顯示「觸控注入：被擋」，請在開發者選項找類似的開關。
4. 用 USB 連上電腦。手機跳出「允許 USB 偵錯」時，勾選「一律允許」再按允許。
5. 執行 `adb devices`，確認裝置狀態是 `device`，不是 `unauthorized`。
6. 測試期間：
   - 開啟「勿擾模式」，避免通知橫幅蓋住畫面。
   - 讓螢幕保持常亮：`adb shell svc power stayon usb`（全部測完後執行 `adb shell svc power stayon false` 還原）。
7. 同時連了多台裝置時，先指定要用哪一台（序號見 `adb devices`）：
   - cmd：`set ANDROID_SERIAL=序號`
   - PowerShell：`$env:ANDROID_SERIAL="序號"`
   - macOS／Linux：`export ANDROID_SERIAL=序號`

### 測試用聊天室

需要兩個聊天室。

**聊天室 A：內容齊全的測試聊天室。** 找一位願意配合的朋友，或用第二支手機、第二個帳號。雙方各發一次下列內容：

| 項目 | 怎麼產生 |
|---|---|
| 單行文字 | 一般訊息 |
| 多行文字 | 輸入時換行；其中一則要含雙引號 `"` |
| 文字夾表情貼 | 文字中插入 LINE 表情貼（emoji） |
| 靜態貼圖、動態貼圖 | 各一張 |
| 連續貼圖 | 連發 3 張，中間不夾文字 |
| 照片 | 單張一次；多張一次（會排成相簿樣式） |
| 直式長圖 | 例如一張手機長截圖 |
| 其他媒體 | 影片、語音訊息、檔案、位置資訊、聯絡人各一 |
| 通話 | 語音通話撥通講幾秒再掛；再撥一次不接 |
| 收回訊息 | 發一則再收回 |
| 回覆訊息 | 長按訊息 → 回覆 |
| 連結 | 一個會產生預覽卡片的網址 |
| 重複短句 | 連發「好」「好」「哈哈」 |

**聊天室 B：長聊天室。** 一個訊息很多的真實聊天室，最好上千則、跨好幾個月。用在測試 5，量滑動行為和「往上捲時載入舊訊息」的停頓。

### 隱私

- 所有輸出都存在 `poc/out/`。這個目錄已加入 `.gitignore`，不會被 commit。
- 截圖、dump、txt 摘要都含有聊天內容。回報結果時，只貼摘要數字和格式樣本，並先刪改私人內容。

## 測試 0：裝置資訊

```
python poc/t0_device_info.py
```

會記錄 Android 版本、廠牌型號、螢幕解析度與 dpi、LINE 版本，並檢查兩件事：

- `input motionevent`：支不支援。不支援時測試 5 的 `--mode hold` 不能用。
- 觸控注入：是否正常。顯示「被擋」時，回到「準備 → 手機」第 3 點，開完開關再重跑。

## 測試 4：截圖

1. 手機打開聊天室 A。
2. 執行：
   ```
   python poc/t4_screencap.py
   ```

腳本會：

- 用 PNG 和 raw 兩種方式各截 5 次，量平均耗時與檔案大小。
- 存一張截圖到 `poc/out/t4_chat.png`。
- 檢查截圖是否幾乎全黑，以及目前視窗有沒有 `FLAG_SECURE`（禁止截圖的旗標）。

判讀：

| 結果 | 意義 |
|---|---|
| 「截圖被擋」 | LINE 禁止截圖，ADB 截圖路線不可行。先停下來回報。 |
| raw 明顯比 PNG 快 | 正式版改抓 raw，由電腦解碼。 |
| 截圖尺寸 ≠ wm size | 手機改過顯示解析度，正式版的觸控座標要換算。 |

另外打開 `t4_chat.png`，用小畫家等工具記下兩個 y 座標：標題列的下緣、輸入框的上緣。這就是聊天區的範圍（測試 2 可以更精確地取得）。

## 測試 2：uiautomator 能不能讀到訊息

`uiautomator dump` 會輸出畫面上每個元件的文字和座標。如果 LINE 有提供訊息文字，正式版就可以不用 OCR，對位會準很多。

步驟：

1. 手機打開聊天室 A，停在只有文字訊息的畫面：
   ```
   python poc/t2_ui_dump.py text
   ```
2. 捲到畫面上有動態貼圖或 GIF 的位置：
   ```
   python poc/t2_ui_dump.py anim
   ```
3. 如果第 2 步失敗，暫時關閉系統動畫再試（結束後會自動還原設定）：
   ```
   python poc/t2_ui_dump.py anim2 --no-anim
   ```
4. 捲到同時有貼圖和照片的位置：
   ```
   python poc/t2_ui_dump.py media
   ```
5. 打開 `poc/out/t2_<標籤>_boxes.png` 檢查：
   - 紅框：有 text 的元件
   - 藍框：只有 content-desc（無障礙描述）的元件
   - 綠框：可捲動的區域

判讀：

| 看到什麼 | 意義 | 對設計的影響 |
|---|---|---|
| 每個訊息氣泡都有紅框，文字與畫面一致 | LINE 透過無障礙介面提供訊息文字 | 文字定位改用 dump，OCR 只當備援 |
| 貼圖、照片有自己的框，或 resource-id／content-desc 能分辨 | 媒體種類可直接取得 | 不需要用影像辨識判斷哪裡是貼圖、哪裡是照片 |
| 聊天區沒有任何紅框或藍框 | LINE 自己繪製訊息 | 必須用 OCR |
| 出現 `could not get idle state` 或耗時超過 5 秒 | 畫面在動時 dump 不能用 | 看 `--no-anim` 能否解決；不行就只在靜態畫面使用或改用 OCR |

摘要中「可捲動節點」那一段會印出 `--top`、`--bottom` 參數，就是聊天區的上下緣，測試 5 會用到。

## 測試 1：貼圖快取

我們唯一找得到的參考資料是 2018 年的腳本，路徑是 `Android/data/jp.naver.line.android/stickers/`。新版 LINE 是否還這樣存，需要實測。

步驟：

1. 手機打開聊天室 A，捲過所有貼圖，讓 LINE 把貼圖下載到手機。
2. 先在手機上查看：
   ```
   python poc/t1_stickers.py
   ```
3. 如果有找到貼圖目錄，拉回電腦分析格式：
   ```
   python poc/t1_stickers.py --pull
   ```

判讀：

| 結果 | 意義 | 對設計的影響 |
|---|---|---|
| `ls` 顯示 Permission denied | 這支手機的 adb 讀不到 `Android/data` | 模組 3b 不可行，貼圖改用截圖裁切 |
| 目錄可讀，但找不到 sticker 相關目錄 | 新版 LINE 不再把貼圖放在外部儲存 | 同上 |
| 找到目錄，格式是 PNG／WebP／APNG，尺寸約 370×320 以內 | 可以使用 | 模組 3b 可做。目錄名稱是數字的話，多半是貼圖組 ID |
| 找到目錄，但格式「未知」且熵接近 8 | 檔案經過加密 | 不可行 |

也請記下：有多少動態貼圖（APNG），以及有沒有 sticon、emoji 相關目錄。

## 測試 3：txt 匯出格式

步驟：

1. 在聊天室 A：右上角選單 ≡ →（其他）設定 → 傳送聊天記錄。不同版本的字樣略有不同。
2. 選一個能存成檔案的方式，例如存到裝置、雲端硬碟，或寄給自己。
3. 把檔案放到電腦。如果存在手機的「下載」資料夾：
   ```
   adb shell ls -t /sdcard/Download
   adb pull "/sdcard/Download/檔名.txt" poc/out/
   ```
4. 執行：
   ```
   python poc/t3_export.py poc/out/檔名.txt
   ```
5. 對照「測試用聊天室」的清單，記下每個項目在 txt 裡長什麼樣子。
6. （選做）把手機的時間格式切換成另一種（12／24 小時制），再匯出一次，看時間欄位是否改變。

腳本會列出：

- 編碼：BOM、換行字元
- 日期行樣式：括號是全形還是半形
- 時間格式：24 小時制、前綴上午／下午、後綴 AM／PM
- 每行用 Tab 分割後的欄位數，以及欄位數不是 3 的範例（通常是系統訊息）
- 所有 `[…]` 佔位符與出現次數
- 疑似系統訊息（通話、收回等）
- 多行訊息的寫法：用雙引號包住，或續行沒有時間戳

請特別確認三件事：

- 自己發的訊息，發話者欄位顯示什麼名字。
- 回覆訊息有沒有包含被回覆的原文。
- 表情貼、連結在 txt 裡變成什麼。

## 測試 5：連續滑動

腳本每一步會：滑動 → 連續截圖直到畫面停穩 → 用前後兩張截圖的重疊區算出實際位移。

步驟：

1. 手機打開聊天室 B，停在最新訊息（最底部）。
2. 基準測試（`--top`、`--bottom` 用測試 2 的數字；沒有就省略，預設取螢幕高度的 15%–85%）：
   ```
   python poc/t5_swipe.py --top 330 --bottom 2050
   ```
3. 對照組：快速滑動。先手動捲回最底部，再執行：
   ```
   python poc/t5_swipe.py --top 330 --bottom 2050 --dur 300
   ```
4. 對照組：拖曳距離加長。捲回最底部，再執行：
   ```
   python poc/t5_swipe.py --top 330 --bottom 2050 --dist 0.6
   ```
5. 到頂與載入停頓：讓它一直捲到停止。聊天很長時可能要 30 分鐘以上，也可以改用較短的聊天室 A。
   ```
   python poc/t5_swipe.py --top 330 --bottom 2050 --steps 300
   ```
6. （選做，測試 0 顯示支援 motionevent 時）放開前先停住，試著消除慣性：
   ```
   python poc/t5_swipe.py --top 330 --bottom 2050 --mode hold
   ```
   如果手機跳出長按選單，代表 input 太慢被判成長按。請按返回鍵，放棄這個模式。

過程中不要碰手機，按 Ctrl+C 可以提前結束（仍會輸出摘要）。每一步的截圖和 `steps.csv` 存在 `poc/out/t5_<模式>_<毫秒>ms_<比例>_<開始時間>/`，同樣參數重跑不會覆蓋前一次。

每步輸出的欄位：

| 欄位 | 意思 |
|---|---|
| 位移 | 畫面實際往下移了幾像素 |
| 慣性 | 位移減去拖曳距離，正值代表放開後還繼續滑 |
| 重疊 | 前後兩張截圖重疊的比例 |
| 分數 | 比對可信度，0.8 以下標為「比對不可靠」 |
| 停穩 | 滑動後多久畫面才停住 |

判讀：

| 指標 | 通過 | 不通過時 |
|---|---|---|
| 最小重疊比例 | ≥ 20% | 調小 `--dist` 或加長 `--dur` |
| 比對不可靠的步數 | 0 | 打開該步與前一步的 step 圖。重疊太少就調參數；若是整段空白或動態貼圖，正式版要改用物件層級的拼接 |
| 慣性標準差 | 越小越好 | 位移不可預測。只要重疊夠，仍然可以拼接 |
| 停穩耗時 | ≤ 2 秒 | 正式版每步要等更久，總時數跟著增加 |
| 停頓後又恢復移動 | 記下最長停頓幾步 | 決定正式版「到頂判定」至少要等多久 |

另外打開幾張相鄰的 step 圖，確認兩件事：

- 浮動日期條、「捲到最新」按鈕出現在哪裡、有多高。
- 每一步大約能看到幾則新訊息。總時數估算 = 每步秒數 × 總訊息數 ÷ 每步新訊息數。

## 測試 6：照片批次下載與對位

步驟：

1. 記錄手機上現有的檔案清單：
   ```
   python poc/t6_media.py mark
   ```
2. 手機：聊天室 A → 選單 ≡ → 照片・影片 → 選擇。多選 10 張以上（含長圖）→ 下載或儲存。記下兩件事：一次最多能選幾張，有沒有出現錯誤訊息（例如照片已過期）。
3. 找出新增的檔案並拉回電腦：
   ```
   python poc/t6_media.py scan --pull
   ```
   會列出新檔案的路徑、大小、解析度、EXIF 拍攝時間。
4. 用聊天截圖裡的縮圖去比對原檔：
   1. 回到聊天室 A，捲到有照片縮圖的位置，執行 `python poc/t6_media.py shot` 截圖。
   2. 用小畫家打開 `poc/out/t6_shot.png`，讀出縮圖左上角和右下角的座標。
   3. 執行：
      ```
      python poc/t6_media.py match poc/out/t6_shot.png --box x1,y1,x2,y2
      ```
   多試幾張，包含長圖。
5. （選做）比較「點開照片再截圖」：在聊天室畫面上，對縮圖中心座標 X、Y 執行下列指令。它會點開照片、等 2.5 秒截圖、再按返回鍵。
   ```
   python poc/t6_media.py viewer X Y
   ```

判讀：

| 看什麼 | 意義 |
|---|---|
| 新檔案的路徑 | 正式版要從哪裡 `adb pull` |
| 解析度 | 可以請對方告知原圖尺寸，確認批次下載拿到的是原圖還是壓縮過的版本 |
| 檔名、修改時間、EXIF | 有沒有可以用來排序或對時間的資訊 |
| `match` 第一名的幾何一致點遠高於第二名 | 特徵比對可以把縮圖對回原檔 |
| `viewer` 截圖的解析度 | 若批次下載不可行，點開截圖能拿到多清楚的版本 |

## 測試 7：聊天媒體快取

測試 1 發現 `Android/data/jp.naver.line.android/files/chats` 有好幾 GB。如果裡面就是照片原檔，正式版可以直接 `adb pull`，不必在手機上手動批次下載。這個測試要在測試 6 之後做，因為它會拿測試 6 下載的原檔來比對內容。

步驟：

1. 確認 `poc/out/t6_media/` 裡有測試 6 拉回來的照片。
2. 執行：
   ```
   python poc/t7_chat_media.py --pull 30
   ```
   檔案很多時，列舉要幾分鐘。

腳本會列出：

- 檔案總數與大小，以及各聊天室目錄的檔案數。
- 路徑規則：把 ID 換成 `<ID>`、長數字換成 `<數字>` 後的路徑樣式，例如 `<ID>/messages/<數字>.thumb`。
- 測試 6 的每一張原檔，在快取中有沒有內容完全相同（MD5 相同）的檔案。
- 該聊天室最舊與最新的檔案，用來看檔名是不是隨時間遞增的訊息 ID。
- 最新 30 個檔案的格式與尺寸。

判讀：

| 結果 | 意義 | 對設計的影響 |
|---|---|---|
| 測試 6 的原檔大多在快取中找到相同內容 | 快取存的就是原檔 | 照片直接從快取拉，不用手動下載 |
| 只找到縮圖（`.thumb` 之類、尺寸小） | 快取只有縮圖 | 照片原檔仍要靠批次下載 |
| 檔名是隨時間遞增的長數字 | 很可能是訊息 ID | 可以依 ID 排序，對回 txt 中 `[照片]` 的順序 |
